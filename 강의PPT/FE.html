01. 진법의 기초 개념과 숫자 체계

📖 진법(Numeral System)이란?

진법은 수를 표현하는 방법으로, 한 자리에서 사용할 수 있는 숫자의 개수를 의미합니다.

• 10진법 (Decimal): 0부터 9까지 총 10개의 숫자를 사용합니다. 우리가 일상에서 가장 많이 사용하는 숫자 체계입니다.

• 2진법 (Binary): 0과 1, 두 개의 숫자만을 사용합니다. 컴퓨터 내부에서 전원(ON/OFF)으로 데이터를 표현할 때 사용됩니다.

💡 10진수와 2진수의 차이점

10진수 자리값 계산
각 자리의 값은 10의 거듭제곱을 기반으로 합니다.
예: 345 = (3 × 10²) + (4 × 10¹) + (5 × 10⁰) = 300 + 40 + 5
2진수 자리값 계산
각 자리의 값은 2의 거듭제곱을 기반으로 합니다.
예: 1011₂ = (1 × 2³) + (0 × 2²) + (1 × 2¹) + (1 × 2⁰)
              = 8 + 0 + 2 + 1 = 11

단위 정리: 비트(Bit)는 0 또는 1을 담는 최소 단위이며, 8개의 비트가 모여 1 바이트(Byte)가 됩니다.

🔄 10진수를 2진수로 변환하는 방법

4. 기록한 나머지들을 역순(아래에서 위)으로 읽으면 2진수가 됩니다.

01. 2진수(Binary)와 진수 변환

핵심 개념 정리

컴퓨터는 전기의 ON(1)과 OFF(0) 상태만 구분할 수 있으므로 모든 데이터를 2진수로 처리합니다.

단위 표현 / 설명 비고
Bit (비트) 0 또는 1 (최소 정보 단위) 1 Bit
Byte (바이트) 8개의 Bit가 모인 단위 1 Byte = 8 Bits
Word (워드) CPU가 한 번에 처리하는 단위 32/64 비트 등

쉬운 예시로 이해하기

[예시 1] 2진수 `1011` → 10진수 변환
오른쪽 자릿수부터 1, 2, 4, 8 가중치를 곱해서 더합니다.
• (1 × 8) + (0 × 4) + (1 × 2) + (1 × 1) = 8 + 0 + 2 + 1 = 11
[예시 2] 10진수 `13` → 2진수 변환
숫자를 2로 나누면서 나머지 값을 아래에서 위로 읽어 올라갑니다.
• 13 ÷ 2 = 몫 6 (나머지 1)
• 6 ÷ 2 = 몫 3 (나머지 0)
• 3 ÷ 2 = 몫 1 (나머지 1) → 1101(2)

  • 비트 연산: XOR(두 비트가 다르면 1), Shift(왼쪽 1비트 이동 = ×2배)

01. SQL 기초 (DDL, DML, DCL)

🗄️ SQL (Structured Query Language)이란?

관계형 데이터베이스(RDBMS)에서 데이터를 조회, 삽입, 수정, 삭제하기 위한 표준 언어입니다.

• DML (데이터 조작어): SELECT(조회), INSERT(삽입), UPDATE(수정), DELETE(삭제)

• DDL (데이터 정의어): CREATE(생성), ALTER(수정), DROP(삭제), TRUNCATE(초기화)

• DCL (데이터 제어어): GRANT(권한 부여), REVOKE(권한 회수)

💡 SQL 기본 조회문 쉬운 예시

[예시 1] 회원 테이블에서 20세 이상 회원 이름 조회
SELECT 이름 FROM 회원 WHERE 나이 >= 20 ORDER BY 이름 ASC;
• SELECT: 보고 싶은 컬럼 지정
• WHERE: 조건 지정 / ORDER BY: 정렬 (ASC 오름차순, DESC 내림차순)
[예시 2] 데이터 수정 및 삭제
• 수정: UPDATE 회원 SET 나이 = 25 WHERE ID = 'user1';
• 삭제: DELETE FROM 회원 WHERE ID = 'user1';

UNIT 01. 키(Key)의 개념 (PK와 FK)

🔑 Primary Key (기본키, PK)

테이블에서 각 행(Row/Tuple)을 유일하게 식별할 수 있는 대표 키입니다.

• 개체 무결성 제약조건: PK는 절대 NULL이 될 수 없으며, 중복된 값을 가질 수 없습니다. (Uniqueness + NOT NULL)

🔗 Foreign Key (외래키, FK)

다른 테이블의 Primary Key를 참조하는 키로, 테이블 간의 관계(Relationship)를 연결합니다.

• 참조 무결성 제약조건: 참조하는 테이블의 PK에 존재하는 값만 가지거나, NULL이어야 합니다.

📊 PK와 FK 연결 예시 (고객 - 주문)

[고객 테이블] (고객ID = PK)
고객ID (PK)이름연락처
C01홍길동010-1111...
C02이순신010-2222...
[주문 테이블] (주문번호 = PK, 고객ID = FK)
주문번호 (PK)주문상품고객ID (FK)
1001노트북C01 (홍길동 주문)
1002마우스C02 (이순신 주문)

STAGE 05. 데이터베이스 (Database)

JOIN (테이블 결합)

02. 여러 테이블의 데이터를 하나로 합치기

🤝 JOIN의 종류와 개념

공통된 컬럼(주로 PK와 FK)을 기준으로 두 개 이상의 테이블을 연결하여 데이터를 조회하는 방법입니다.

1. INNER JOIN (내부 조인)
양쪽 테이블에 모두 존재하는 일치하는 데이터만 결합하여 조회합니다.
SELECT A.이름, B.상품 FROM 고객 A INNER JOIN 주문 B ON A.고객ID = B.고객ID;
2. LEFT OUTER JOIN (왼쪽 외부 조인)
왼쪽 테이블의 모든 데이터와 오른쪽 테이블의 일치하는 데이터를 가져옵니다. (오른쪽에 데이터가 없으면 NULL 표기)
3. RIGHT OUTER JOIN / FULL OUTER JOIN
• RIGHT: 오른쪽 테이블 기준 모든 데이터 가져오기
• FULL: 양쪽 테이블의 모든 데이터 가져오기
3
UNIT 02. Index와 Transaction (ACID)

⚡ Index (인덱스) - 빠른 검색의 핵심

• 책 뒤의 '색인'처럼 데이터 검색 속도(SELECT)를 향상시키기 위해 사용하는 기술입니다.

• 주의점: 인덱스를 과도하게 생성하면 INSERT, UPDATE, DELETE 성능은 오히려 저하됩니다.

🔄 Transaction (트랜잭션) & ACID 원칙

데이터베이스의 상태를 변화시키는 하나의 하나의 작업 단위(예: 계좌 이체)입니다.

🔥 시험 필수 암기! 트랜잭션의 ACID 4특성
  • A (Atomicity, 원자성): All or Nothing. 모두 성공하든지 모두 취소(Rollback)되어야 함.
  • C (Consistency, 일관성): 실행 전후에 DB의 제약조건과 일관성이 유지됨.
  • I (Isolation, 고립성/격리성): 수행 중인 트랜잭션에 다른 트랜잭션이 끼어들 수 없음.
  • D (Durability, 영속성/지속성): 성공적으로 완료(Commit)된 결과는 영구 보장됨.

FE 기본정보기술자

01. 선형 자료구조 (Stack & Queue)

📚 스택 (Stack) - LIFO

• 후입선출 (Last-In, First-Out): 가장 나중에 들어간 데이터가 가장 먼저 나옵니다.

• 주요 연산: Push(삽입), Pop(삭제), Top/Peek(맨 위 확인)

• 사용 예시: 웹 브라우저 뒤로가기, 함수 호출 스택(재귀함수), 실행 취소(Undo)

🚶‍♂️ 큐 (Queue) - FIFO

• 선입선출 (First-In, First-Out): 가장 먼저 들어간 데이터가 가장 먼저 나옵니다.

• 주요 연산: Enqueue(삽입), Dequeue(삭제)

• 사용 예시: 프린터 인쇄 대기열, 작업 스케줄링, 버퍼(Buffer)

💡 스택과 큐 쉬운 비교 예시

• 스택(Stack): 프링글스 과자통 (나중에 넣은 맨 위 과자를 먼저 집어 먹음)
• 큐(Queue): 버스 정류장 줄 서기 (먼저 줄 선 사람이 먼저 버스에 탑승함)

UNIT 01. 연결 리스트 & 트리 (Tree)

🔗 연결 리스트 (Linked List)

• 데이터(Data)와 다음 노드를 가리키는 포인터(Pointer)를 묶어서 연결한 구조입니다.

• 장점: 데이터의 삽입/삭제가 매우 용이함 (포인터 연결만 변경하면 됨)

• 단점: 특정 번째 노드를 찾으려면 처음부터 차례대로 탐색해야 함 (배열보다 접근 속도가 늚)

🌳 이진 트리 (Binary Tree) & 순회

각 노드가 최대 2개의 자식 노드를 가지는 계층형(비선형) 구조입니다.

• 전위 순회 (Pre-order): Root → Left → Right

• 중위 순회 (In-order): Left → Root → Right (이진 탐색 트리에서 정렬된 값 출력)

• 후위 순회 (Post-order): Left → Right → Root

📊 트리 순회 예시 (Root: A / Left: B / Right: C)

순회 방식방문 순서설명
전위 (Pre)A → B → C루트를 가장 먼저 방문
중위 (In)B → A → C루트를 중간에 방문
후위 (Post)B → C → A루트를 가장 나중에 방문

정렬 및 탐색 알고리즘

02. 데이터 탐색과 정렬의 원리

🔍 탐색 알고리즘 (Search)

• 순차 탐색 (Sequential Search): 처음부터 끝까지 하나씩 찾아가는 방식. $O(N)$

• 이진 탐색 (Binary Search): 정렬된 데이터의 중앙값과 비교하여 범위를 반으로 줄여가는 방식. $O(\log N)$

🔄 주요 정렬 알고리즘 (Sorting)

1. 버블 정렬 (Bubble Sort) - $O(N^2)$
인접한 두 요소를 비교하여 크기 순서대로 자리를 계속 바꾸는 가장 단순한 알고리즘입니다.
2. 퀵 정렬 (Quick Sort) - 평균 $O(N \log N)$
피봇(Pivot)을 기준으로 작은 값과 큰 값을 분할(Divide & Conquer)하여 정렬하는 매우 빠른 알고리즘입니다.

UNIT 02. 시간 복잡도 (Big-O Notation)

⏱️ Big-O(빅오) 표기법 - 성능 평가

알고리즘이 실행될 때 데이터 수($N$)에 따라 걸리는 시간의 증가율을 표현한 것입니다.

빅오 표기법명칭대표 예시
$O(1)$상수 시간배열 인덱스 접근, 스택 Push/Pop
$O(\log N)$로그 시간이진 탐색 (Binary Search)
$O(N)$선형 시간순차 탐색, 단일 for문 탐색
$O(N \log N)$선형 로그 시간퀵 정렬, 병합 정렬
$O(N^2)$이차 시간버블 정렬, 이중 for문

  • 스택(LIFO) vs 큐(FIFO)의 개념 구분 문제는 단골 문제입니다.
  • 이진 탐색은 반드시 데이터가 '정렬'되어 있어야 사용할 수 있습니다!
  • 트리 순회 문제는 루트(Root)의 방문 위치를 기준으로 판단하세요.
